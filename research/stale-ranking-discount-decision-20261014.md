## 1. 问题一句话

**「过期未复审」的条目，该不该在检索排序里打折？**——现状是「**显示降档、排序不动**」；材料要裁的就是要不要把这两层连接起来。

## 2. 现状（精确定位到代码，不是印象）

**stale 已有完整检测**（`credibilityOf`，lib.mjs）——三类各带锚与阈值，阈值在 `CRED_DEFAULTS = { snapshotDays: 90, evergreenDays: 180, verifyUsageMin: 3 }`：

| 类 | 锚 | 过期判据 |
|---|---|---|
| snapshot（id 尾 `-YYYYMMDD`） | `last_reviewed`（链尾） | 龄 > **90d** |
| frontier | `next_review` | 到期即 stale |
| evergreen | max(最近 `verification.at`, `last_reviewed`) | 龄 > **180d** |

**两层今天怎么用**：
- **展示层**：`displayTier = stale ? dropTier(tier) : tier` —— 过期**降一档显示**，并在命中行标「**待复核**」（lookup/ brief 都有；lookup 说明句原文：「待复核只是展示」「层级系数只影响排序」）。
- **排序层**：`rankFactors.weight = refuted ? 0 : TIER_WEIGHT[tier]` —— **用原 tier，不看 stale**。即：**过期目前不影响排序**。
- 排序里现有的其它权重源（供对照）：refuted→0；**over-quota 使用量校正（A1，默认关）**；类别模板 severity×complexity；`RANK_DEFAULTS.loadBalance: false`（负载均衡默认关）。

⇒ 「stale×排序折扣」的**真实决策点只有一处**：**`weight` 要不要改用 `displayTier`（或另设 stale 乘子）**。

## 4. 三个选项

**A. 维持现状（显示降级已足够）**
过期只降**展示**档 + 标「待复核」；排序权重不动。
- 理由：① 排序改动需样本校准，现在 0 样本；② **stale ≠ 不可信**——老条目常是基础条目（纪律/红线/称呼），「无据的确定 ≪ 有据的不确定」钉的是**据**不是**龄**；③ 展示层的「待复核」已经把信号给到模型与人，且**不改变命中可得性**（不会把老条目藏起来）。
- 风险：模型可能忽略「待复核」标记、照旧按高 tier 采信。

**B. 温和折扣（weight 改用 displayTier）**
stale ⇒ 排序权重降一档（等价于把展示降档接到排序上）。
- 参数：仅对既有三类 stale 生效；不改可见性；`TIER_WEIGHT` 映射不变。
- 风险：仍缺校准样本；若「过期但高频引用」的条目很多（库越老越可能），会持续压低真正有用条目的排序——**B 方案最好带自限条件（并入 C）**。

**C. 双条件折扣（与 I-15 同构，推荐备选）**
仅 **stale ∧ 窗口零引用 ∧ 链无 verification**（三项全中）才打折（乘子如 ×0.85，或降到 displayTier）。
- 理由：把「老」收窄成「老且没人用且没被验证过」——这是唯一同时有**衰减语义**与**证据条件**的形态；与 I-15 建议线同判据，一致性好。
- 风险：条件苛刻 ⇒ 触发率极低（可能就是设计目的）；「零引用」依赖 hooks usage 线可读（不可读时**不假报**，跳过——I-15 已声明此纪律）。

## 5. 推荐：**A 先 + 立「重议判据」；B/C 预置待数据**

任何候选方案在库龄 <90d、due=0 的今天都没有校准样本；现在动手＝凭喜好调因子。建议：

1. **先维持 A**（零改动）；
2. **注册重议判据**（一有信号就回来裁）：`audit --due` 首次出现到期条目，或 `credibility-decay` 首次非零，或 evergreen/snapshot 首批 stale 出现——届时记录两个数：**「stale 且被引用」条数** vs **「stale 且零引用」条数**。前者多 ⇒ 是复审节奏问题（该安排复审），后者多 ⇒ 支持 C 方案打折；
3. **若届时选 B/C**：按既有「**排序因子观察期**」制度走——先加开关（默认关，同 `loadBalance` 形态）、影子对照若干天、再定默认；打分**只进排序、不改可见性与当前集**（沿用 wave3 声明）。
