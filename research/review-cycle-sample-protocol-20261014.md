# 小样本子 agent 复审协议（草稿，2026-10-14）

只读协议。本文件不改六库、不自动派审、不自动修订。自动化闭环可以以后再接；这一步只把流程、样本窗和宪章写死，并挂到已有的只读 `audit`。

依据：`core/PROTOCOL.md` §十四（I-10 复审四步）。本草案把「一次审多少」从「全部到期」收成**核心档小样本**。

## 宪章（原文，须原样进入抽样结果）

不给压力：复审是对照，不是考核。子 agent 不必凑出问题才算完成；「维持」与「没有更好的解法」是合格结论。不设「必须找出 N 处错误」的配额，不因零疑点而重审，不把到期条数当成未完成的债。小样本（5–10 条核心到期）按排期做完即可停。

代码常量：`REVIEW_CHARTER_NO_PRESSURE`（`core/lib.mjs`）。`reviewSample` 与 `audit().review.sample.charter` 带回同一句。

## 样本窗

- 母集：`reviewDue` / `audit --due` 里 **`intervalDays === policy.coreDays`（默认 30）** 的到期条。一般档与年审不进这一轮小样本。
- 窗：**5–10 条**。默认取 8。`limit` 再大也不超过 10。核心到期不足 5 条时**如实少取，不凑数、不降档补齐**。
- 顺序：沿用到期清单已排好的序（逾期天数，其次库名与 id）。不另打乱，避免同一天两次抽样对不上。

只读入口：`reviewSample({ due, limit })`。`audit()` 把结果放在 `review.sample`。不写库、不写 review-log、不调用模型。

## 四步（排期 → 审查 → 修订链追加 → review-cycle 留痕）

1. **排期**  
   `audit --due`（或 `audit().review.sample`）取出本轮核心样本。记下 `window.taken` / `window.coreDue` 与每条 `{store, id}`。样本做完即可停，其余到期留到下一轮。

2. **审查**  
   对样本中每一条：`review pack <id>`（输入包强制全文，不受日常 show 硬顶）→ 交给 **fresh 子 agent**（零上下文）。三问仍是事实、方法、是否失效。建议动作 ∈ 修正 | 升级 | 维持。  
   「维持」和「没有更好的解法」是合格结论。零疑点不用重审。

3. **修订链追加**  
   主会话对照报告裁决（报告是材料，裁决权在主会话）：
   - 修正 / 升级 ⇒ `revise` **追加**新版本（原文行不改、不删）；
   - 维持 ⇒ 不改正文，只在下一步打复审戳。

4. **review-cycle 留痕**  
   无论裁决如何，都 `review log <id> --verdict <维持|修正|升级>`，写入 `logs/review-log.jsonl`（`review-cycle` 事件）。维持会给 `last_reviewed` 打复审戳。`review list` 可读回。子 agent 与主会话结论冲突时如实并记，不合并成一条。

## 这一步做到哪、下一步不做什么

- 已有：协议正文、宪章原文、`reviewSample`、`audit().review.sample`。
- 未做（可分步）：到期自动排队、子 agent 投递、审查报告回写、未完成样本的催办。这些都还要人工走 CLI。
- 明确不做：用样本完成率当考核、为了凑满 5 条去改间隔、为了找出 N 处错误而重开一轮。
