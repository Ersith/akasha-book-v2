# 控制论视角的两件事：阿卡夏的均衡化，与"肌肉记忆"的 PID 路径

> 2026-10-09 立。触发：Qwen 「ID Balancing」（arXiv:2609.39137，见 frontier `front-qwen-id-balancing-2026`）——把 MoE 负载均衡从"加辅助 loss"改成"PID 闭环控制"。启发来源类别：**控制论迁移**（不是架构创新）。
> 本文两问：①它对阿卡夏之书的维护/优化有什么可借鉴？②"肌肉记忆"（权重内化）若搞，以它的思路怎么达成？

## A. 对阿卡夏的借鉴（维护与优化方向）

**A0. 总纲：我们家里的"分配系统"都在开环跑**
ID Balancing 的本质：*给一个分配系统装误差反馈*。阿卡夏里至少有三处同类分配系统，当前都**开环**：

**A1. 检索负载均衡（最高价值，= 我们的"专家路由"）**
- 病灶：热门条目反复命中（hot canon 垄断注意力）、冷条目饿死（永远埋没）——与 MoE 死专家同构。
- 现成料：`hooks.jsonl` 的 `usage` 计数 + `metrics` 已有逐条引用统计 → **误差信号现成**。
- 机制设想（观察期后评估）：在排序四因子上加**均衡修正项**——
  - 主动量：条目近期被引用次数 vs 该库/该来源的软配额（误差 e）；
  - 修正：e 超阈 → 降 boost（防垄断）；长期零引用且被弱命中 → 加探索项（防饿死）；**恶化速率**（引用集中度上升斜率）触发提前刹车（D 项思想）；
  - 硬约束：修正项**只动排序、不改语义**（不隐藏、不删条；与 pricing/credibility 正交），可关、可审计。
- 与既有纪律的对齐：清理原则"**保险逻辑**（orphan 零权重留档）"的延伸——防的是"注意力的幸存者偏差"。

**A2. 上下文预算分配（装载有界）** — **已落地（wave4，默认关；修订：冗余优先）**：`allocateContextBudget` + `placeWithRedundancy`/`nearestFetch`；验收 `phaseResidueSample`（best−worst gap）。padding/align 仅实验对照——客户端无法对齐 provider 相位。self/usage 豁免敌对缩额。见 `SCHEMA.md`「A2」。
- 病灶：每次注入给各来源的额度是**静态**的（self/usage/kit/会话层/检索片段）。
- 误差信号：各来源"最近是否救过场/是否长期无用"（可从回查、命中、任务结果反推）。
- 机制：额度按误差微调（救场→加额；长期空转→减额），同样"小误差小更新、恶化才刹车"。

**A3. 睡眠计划（批处理，低优先）**
- sleep --plan 的合并/丢弃是批处理决策，均衡性要求低；只借一点：**把"恶化率"纳入候选排序**（比"当前状态"更早发现腐化）。

**A4. 统一框架（方法论借鉴，成本零）**
- 该文最漂亮的手艺：**把两个 competing 方案统一成同一控制器族的缺失项**（DeepSeek=固定步长 I、Kimi=广义 P）。我们的对应动作：用"控制器"视角重述**排序四因子 + 时间衰减 + 情绪 boost**——现在它们是谁也不管谁的**开环参数**；借控制视角逐条问：这个因子的**误差信号**在哪？有没有反馈？没有反馈的，就是"祈祷式参数"（等同 aux loss）。

**A5. 指标纪律（aux-loss 教训的移植）**
- aux loss 的教训：**辅助目标不能污染主目标**。对应纪律（写进候选）：任何优化项（配额/boost/均衡修正）**必须可关、可审计，且只做修正、不做替代**——排序主语义（相关性/可信度）永不被优化项改写。

## B. "肌肉记忆"的 PID 路径（若搞，怎么达成）

**B0. 一句话**：不是"设计一份完美训练配方一次成型"，而是**在睡眠期跑一个 PID 闭环的持续内化**——误差来自我们自己的考官，执行器分三档，误差越大修正越强、只在恶化时刹车、只碰程序层不碰事实层、全程可回滚可审计。

**B1. 控制器四要素（照 ID Balancing 的骨架搭）**
- **被控对象（plant）**＝模型行为分布，观测量＝评测向量（纪律遵守率 / 来源态正确率 / 对照纪律出现率 / 编造率 / 检索自觉率 / 空转率…）；
- **误差（e）**＝期望 − 实测，**考官现成**：`MEMORY-TEST` + 回放家族 + B2 计数 + 我们对外的独立复检流程；
- **执行器（actuator）＝三档，对应 PID 项**：
  - **档 0 · 比例项（随时、零成本）**：提示层纠偏——常驻注入 / 钩子补强 / 简报改善（即我们已定的"不碰权重"路线）；
  - **档 1 · 积分项（累积触发）**：误差**持续存在**才积累"训练样本"（反复做错的场景 → 微调数据；pricing → DPO 偏好对）。**积分=不见兔子不撒鹰**：偶发噪音不触发，持续误差才立项；
  - **档 2 · 微分项（提前刹车）**：**漂移率监控**——某维度恶化**斜率**超阈 → 提前降权/卸载 LoRA，不等崩坏（对应其"derivative 仅在恶化时激活"）。
- **周期（何时调）**：**睡眠期**——离线、批量、可审批，与人类巩固发生在睡眠同构；sleep 现在巩固「库」，未来同一条流水线可产出「训练 batch」。

**B2. 稳定性经验（该文最值钱的四条，直接抄）**
1. **误差大 → 修正强**（其"integral scales with error"）→ 评测差距大才激进，接近目标就小步；
2. **恶化才刹车**（其"derivative 仅在 worsening"）→ 平时不抖，避免过冲/震荡；
3. **近平衡时小更新**（"smaller updates near balance"）→ 防止把已达标的维度调坏；
4. **不污染主目标**（"no auxiliary loss"的精神）→ **训练只学纪律/偏好层（L1 价值排序、L2 决策结构），不熔事实**；用**可插拔 LoRA + 冻结主体**实现，事实继续走库（保"换模型不换大脑"）。

**B3. 验收与安全（缺一不开工）**
- **双门**：A/B 对照（有/无内化版本跑记忆测试+回放集）+ 复测三态（不达门槛＝inconclusive → 不合并）；
- **可回滚**：LoRA 卸载即回原状；
- **审计链**：数据集版本 + 评测记录 + 批准人；**内化不能吞掉"它是怎么长出来的"**；
- **红线**：不做"全能训练"；只覆盖程序性/纪律性维度；不把事实记忆熔进权重。

**B4. 前置条件（现在缺什么）**
1. **可训练的对象**——现有 API 模型不可训（本地开源权重或开放微调接口是前提）；⇒ 现状=**只积累、不训练**；
2. 评测自动化——大部分已有（MEMORY-TEST/回放/B2/复测），需补"漂移率"统计；
3. 数据打包——**现在就能开始**：给"高频、稳定、已被验证"的纪律条目打标 → 训练包导出（此前预留的口）。

**B5. 一句话对外口径**
> 后训练是"把知识熔进肌肉"；我们给它装的是**恒温器**——误差来自自家考官、修正分三档、恶化才刹车、只熔工序不熔事实、随时可拔。
