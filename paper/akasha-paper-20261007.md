## 摘要

语言模型智能体存在结构性「记忆赤字」：权重内的记忆不可审计、不可更正；纯提示的记忆随会话消亡；而把一切写进备忘录的做法又会因「读写成本倒挂」（写便宜、读昂贵）导致记录无节制膨胀。本文提出**阿卡夏之书（Akasha）**——一个模型无关、文件式、**可审计**的外置记忆层。其核心主张有三：（1）**六库分工**：把记忆按用途而非仅按认知类型切分为稳定库（canon）、镜像库（mirror）、孤案（orphan）、定价表（pricing）、情绪词表（lexicon）、文献基石（frontier），各自带独立复核周期；（2）**可审计的演化**：append-only 存储 + 修订链（supersedes，不提改原文）+ **双时态**（事件时间 `event_time` 与记录时间 `logged_at` 分离）+ 写入门控，使「何时发生的 / 何时记下的 / 何时被改的」三问皆可回答；（3）**纪律依赖分层**：以「软协议 → 机检 → 审计与定价」三层强制力承载输出纪律（来源态四标签、无据的确定 ≪ 有据的不确定），并公开承认其边界（协议是概率修正，不是约束求解）。系统以零依赖 Node 实现，经 MCP 工具面（17 工具）与宿主插件（两条 runtime 条子：睡眠摘要 / 库脉搏+回查；唤醒条；写入门控；会话层调度与循环观测）接入 DSH 桌面端，在真实运营中积累四十余条稳定知识、89 条文献基石、77/77 自动测试，支撑两轮跨会话的「测试期冻结—受控解冻—两轮复查」治理循环，并落地输出审计与使用计数 v0（对不存在的库 id 引用自动标记）。2026-10-07 起系统扩展出**会话层（小阿卡夏）**：把宿主会话档案（**含被上下文压缩折叠的历史**）抽取为段级条目并**结论优先**检索，其上构建机械递归的**弧线树**（L1 弧 / L2 幕、代际管理），以 ptr 回原档提供全保真通道；同层落地**循环观测 P0（dry 干跑）**——三层环（流环 / 回合环 / 事后环）只观测不干预，基于「流式帧为进程内瞬态、revision 逐帧递增」等源码级真值修正检测路径；其首窗产出的第一批数据同时构成了对观测环自身的修正（含一类跨组件通病：「夹具失真」——测试按作者想象而非宿主真值塑形）。全部资产可导出并可移植——换模型不换大脑。

**关键词**：智能体记忆；外置记忆；可审计性；修订链；双时态；离线巩固；记忆治理

## Abstract

Language-model agents suffer a structural "memory deficit": knowledge in weights is neither auditable nor correctable; prompt-borne memory dies with the session; and naively journaling everything explodes under an inverted read–write cost ratio. We present **Akasha**, a model-agnostic, file-based, *auditable* external memory layer for LM agents. Three claims: (1) **six purpose-typed stores** — canon (stable knowledge), mirror (narrative schemata), orphan (zero-weight anomalies), pricing (behaviour pricing), lexicon (affect terms), frontier (literature bedrock) — each with its own review cadence; (2) **auditable evolution** — append-only storage with a supersession chain (never rewriting the original), **bi-temporal fields** (event time vs. logging time), and write-gating, so "when it happened / when it was recorded / when it was revised" are all answerable; (3) **layered enforcement** — soft protocol → machine-checkable gate → audit-and-pricing, carrying output disciplines such as provenance tags and the ranking nail "unfounded certainty ≪ founded uncertainty", with its limits stated honestly (a protocol is a probability shift, not a constraint solver). The system is a zero-dependency Node implementation exposed via an MCP tool surface (17 tools) plus host plugins (two per-turn strips — a sleep summary and a library pulse with failure-recall — a wake note, write gating, and a session-layer scheduler with dry-run loop observability) on the DSH desktop platform. In real operation it accrued forty-plus canon entries and 89 literature bedrocks with a green 77/77 test suite, sustained two rounds of a cross-session governance loop (freeze → controlled unfreeze → two-pass review), and shipped an output-audit and usage-counting v0 stage (references to non-existent store ids are flagged automatically). A companion **session-memory layer** (little-Akasha) indexes host session archives — including context-compacted history — into conclusion-first segments with a recursive arc tree and pointer-level fidelity, and hosts a **dry-run loop-observability ring** (stream / turn / post-hoc) that corrected five cross-component defects in its first window without ever intervening. All assets are exportable and portable: swap the model, keep the brain.

**Keywords**: agent memory; external memory; auditability; supersession chain; bi-temporality; offline consolidation; memory governance

## 1. 引言

### 1.1 问题：记忆赤字与三个失效模式

语言模型在会话间是无状态的。工程上对此有三种典型回应，各有失效模式：

1. **权重化**（微调 / 知识编辑）：记忆不可审计、不可更正、不可迁移，且更新代价高。
2. **提示化**（系统提示 / 备忘文件）：会话终止即消亡，容量受装载预算刚性约束，且没有更新纪律。
3. **日志化**（把一切写进备忘录）：由于「写 ≈ 零成本、读（进上下文）昂贵」的**读写成本倒挂**，记录无节制膨胀；人类记忆之所以不爆炸，恰因为其读写成本结构相反（编码贵、回忆便宜）——人类在写入侧就完成了压缩。

三者共同的缺口是：**记忆的写入、更正与复核都不承担纪律**。当记忆成为智能体行为的一部分时，一个不可审计、不可更正、不可复核的记忆层本身就是可靠性风险。

### 1.2 本文贡献

本文提出并实现**阿卡夏之书（Akasha）**，四个贡献：

1. **架构**：六库分工的用途型记忆架构（§3.2），每库有独立字段规范、复核周期与写入门槛；以「库无界、装载有界」与「写入与整理分离」为总原则（§3.1）。
2. **可审计的演化机制**：append-only + 修订链 + 双时态 + 门控（§3.3），并配套**来源态四标签**输出纪律（§3.4）与**情绪定价 / 孤案**两个非典型库（§3.5）。
3. **检索与回忆工程**：四源路由、弱/强分层计分（子词回退）、时间过滤与时间坐标（§3.6）；离线巩固的「睡眠」机制（§3.8）；**单会话记忆层**——段抽取、结论优先检索、弧线树导航与循环观测 P0（§3.9）。
4. **实现与运营报告**：零依赖实现 + DSH 插件生态接入（§4）；连续运营数据与两轮跨会话治理循环（§5），含失败模式复盘（§6.2）与同族举一反三（§5.3）。

### 1.3 缘起：一条推演链（为什么会有这个项目）

> 本节追记项目诞生的**逻辑过程**——从「真实遭遇的问题」到「设计公理」的推演链；每一步都来自 2026-09-27 至 10-07 的实际事故与讨论（事件均在案），本节只做梳理，不做事后美化。

**起点不是「想要一个记忆系统」，而是三类问题在同一周内同时暴露：**

1. **跨会话遗忘（工具性）**：与语言模型的长期协作中，会话一结束，上一会话的判断、教训与结论全部蒸发；一次桌面端重启就是一次「失忆事件」，知识传递靠人肉转述与运气。
2. **记忆不可审计（可靠性）**：既有的记忆手段（模型权重、系统提示、散落的笔记）都答不了三个基本问题——**这条信息哪来的？什么时候改的？改之前是什么？**当协作内容涉及「要不要重启」「能不能删」「装不装」这类不可逆决策时，不可审计的记忆＝不可追责的决策基础。
3. **格式与主权（工程性）**：同期并存的现成记忆层（宿主知识页 / OpenViking）各有最优场景；评估结论不是「它们不好」，而是：与其把项目的判断力绑定到某一家的存储格式与更正语义上，不如自建一个**格式自有、可审计、模型无关**的档案层，与既有记忆层**并联而非合并**（实证：三方数据层完全隔离、提示层相邻共存）。

**推演链（每一步＝遭遇问题 → 推演 → 落成的公理 / 机制）：**

| # | 遭遇的问题（真实事件） | 推演 | 落成的公理 / 机制 |
|---|---|---|---|
| 1 | 插件升级后整段功能**静默消失**，零日志、无报错（10-06 事故） | 「无观测＝不可运维」同样适用于记忆：写入、失活与拒绝都必须留痕 | 全链路观测线（armed / error 线）；一切写入落 `hooks.jsonl` |
| 2 | 追查依赖时「搜不到引用 ≠ 没用途」，险些误删（09-28） | 记忆的价值不能只用「被读到的次数」衡量；但**可用性**应当可计数 | 使用计数 v0（引用命中线）；档案纪律「只搬不删」 |
| 3 | 生成器重跑可能抹库；报告同日覆盖可能毁掉当次记录 | 任何「整理」动作都可能破坏历史 ⇒ 整理必须与写入分离，且**永不覆写** | append-only；修订链（supersedes，不改原文）；报告时间戳后缀 |
| 4 | 长会话被上下文压缩吃掉细节，「吸收」与「理解」挤在同一时刻 | 需要把吸收与理解在时间上分开（人类睡眠的启发；Sleep-time Compute 同向） | 睡眠：空闲 / 定时 / 手动三触发；**追加式**蒸馏产出 |
| 5 | 人类记忆不爆炸而备忘录必然膨胀 | 读写成本倒挂 ⇒ 在写入侧完成压缩的机器等价物 | 「库无界、装载有界」；**写傻读精**（在线只追加不判断） |
| 6 | 模型会「客气地编造」——无据却笃定 | 诚实必须被投影成工序（不可检的德行 → 可检的字段） | 来源态四标签；排序钉子「无据的确定 ≪ 有据的不确定」；零编造红线 |
| 7 | 「必定执行」做不到——协议只是概率修正 | 强制力只能分层购买：可机检的才承诺「必定」 | 软协议 → 机检（`check` / 门控）→ 审计与定价三层 |
| 8 | 记忆一旦可写，就会写烂 / 写僵 | 烂 = 审计与错价；僵 = 格式绑定 | `audit`（到期 / 陈旧 / 重复 / 积压）+ 定价；「换模型不换大脑」 |

**为什么是现在、为什么可行：**宿主生态（插件面 + MCP + 钩子 / 门控能力）第一次凑齐「进程外记忆层」的全部载体；而协作历史里已积累**高密度的真实失败样本**（静默失活、磁盘爆满、覆写风险、测试污染）——它们既是需求证据，也是现成的设计测试用例。换言之：**需求不是被假设的，是被事故逼出来的**；每一条设计公理背后都有一件确凿发生过的事。

**这条链直接指向的结论：**语言模型作为长期协作对象，其记忆不能只存在于会话内、权重内或人的转述里——它必须是一个**外部的、可审计、可更正、可复核**的层。「外置大脑」不是产品偏好，而是上述约束下被推出来的解；阿卡夏之书即是该结论的工程化。

### 1.4 源起弧线：一场五轮对话

> 本节展示逻辑的**生成现场**——素材为项目源头讨论的**原始存档**（2026-10-06「AI 记忆架构」讨论，存于跨会话记忆库；引号内为讨论原文，仅作节选与衔接润色）。这不是一次问答，而是**五轮往返**：从一次游戏事故出发，每一个公理都在驳斥与修正中成形。以下按原始顺序完整呈现。

**第一轮 · 观察：「AI 时刻在看记事本」**

> ——「我发现个有趣的事。我现在认为 ai 处于形成意识的初期。在思维上 ai 现在都是通过 agent、md 之类的写下记忆或者说经验与坑。而人类更多是依靠潜意识。**就比如 gpt 完 mc 被苦力怕被炸了以后，因为这件事开始反复的去做防御条规写入 md 这样的备忘录，最后导致被撑爆上下文，开始疯狂种土豆这件事。**人类则会因为被炸后，潜意识记住苦力怕会爆炸，离远点。自身大脑快速判断出其中的关键性，也只记忆这点，不会记录额外的规则。而 ai 在这个方面上基本上不会去判断我记下这些是否需要精简。就像是 **AI 时刻在看记事本**，但人类不可能时刻看记事本，所以依靠简短关键词句联想记忆在潜意识里。」

**第二轮 · 拆解：潜意识被冻结了**

> ——「你这套观察里最锋利的是那句『AI 时刻在看记事本』。但有个关键修正会让它更准：**AI 不是缺潜意识，是潜意识被冻结了。**模型的权重就是它的潜意识——几十亿参数的分布式关联表征……问题在于普通部署里权重出厂即冻结，它没法把『被炸』这个经验写回参数，于是只能把经验写成便签，每次开机重读所有便签。**外置记忆不是 AI 的思维特征，是权重不可改的补偿机制。**」
> ——「**便签只增不减的原因：读写成本倒挂。**人类写记忆贵——要专注、要重复、要付出情绪代价；读记忆便宜——联想几乎免费。AI 反过来：写便宜，一拍脑袋生成一条 md；读昂贵，每条都占 token。……**记录没有代价，就没法给记忆定价。**人类的定价器是痛感……而且它存的是稀疏索引，不是防御条规第 1 到 7 条。」
> ——「**带宽悖论。**……同样是『记不住』，人类那边是细节掉线、抽象留下、反应变快；AI 那边是行为降级。**种土豆不是遗忘，是故障。**」
> ——「缺的一环是**睡眠**。人类白天攒的琐碎经验，在慢波睡眠里被海马体批量重放、压缩、抽象，最后写进皮层……现在的 AI 只有醒着的积累，没有离线巩固。……它卡在文明的一个特定阶段：**发明了文字，但还没发明遗忘，也没有分层索引。**」

**第三轮 · 设计：「搞个类似图书馆的信息库」**

> ——「那么实际上可以搞类似图书馆的信息库。把记忆封装，通过关键词联想，和时间以及成因、结果为依据进行调度，这样可以最大限度的降低昂贵的记忆查阅？同时在非用 ai 期间，让 ai 写一个根据经验和分类的自动化整理规则的工具……之后就可以经过时间上的经验积累定期提升这种压缩规则的能力？」
> ——（设计回复节选）「方向可行，有先例……你的增量里最值钱的是**因果当检索键**——『这情况会引出什么』和『这故障由什么导致』两个方向都能查。但照直建有三个必踩的坑：① 索引自己会变成新记事本（每层宽度封顶、增长赶到深度）；② 时间别当检索主键（应为生命周期属性 + 打分修正）；③ **写入和整理分离，判断只在线下花**（在线 append-only，离线蒸馏）。……『定期提升规则』要外部指标，不能自评。」

**第四轮 · 驳回：「有几点我不同意」**

> ——「有几点我不同意。首先记事本这事，本身记事本变多大都没关系，重点在于你**是一次性全读，还是检索**。……人类不会为了查一个事把记事本完整读一遍，而是通过关键词、时间、成因和结果来快速回忆。所以**时间也是很重要的**，人类认识世界的很大一个标尺也是时间。而分离和整理是需要加入自己判断的……等一类事情有了某个数量的基准经验的时候就可以完全依靠自动化，之后则随着时间推移不时拿出来以自己提升的智能去优化再认知——这就像是对应了人类时间线上的成长。规则提升实际完全可以靠自身评判：对某一类事情的成功率，失败程度，可优化空间，做事的成熟程度，都可以作为依据。」

**第五轮 · 修正：结两笔账**

> ——「先结两笔账——上一轮我有两处说过了头。**库的尺寸 vs 装载的尺寸，我混了。**你是对的：库本身可以无界，以『上下文 token』为货币，库变大近似免费。……真正的不变量只剩一条：**每轮进上下文的量有预算**，整读权只留给一页极小的『无条件反射』。**时间，让位，你对**——它是因果的排序基底，不是 TTL 元数据。……『完全依靠逻辑』要成立，得把**定价显式写成目标函数**：严重度 × 不可逆性 × 代价（时间、回滚、数据）。……**不是不能自评，是不能靠内省自评**——堵法：指标接线（红线条目 / 回滚次数 / 差点不可逆）+ 历史回放（拿旧事故当考题，新规则重跑一遍）。」
> ——（收敛句）「**存储无界 → 每轮上下文是查询结果而非文档 → 整读只剩一页无条件反射 → 蒸馏/合并/废弃是带阈值的后台活 → 规则改良由结果计数器自评、由历史回放验证、由升级模型定期再加工。**对应人的话：检索=联想，反射页=条件反射，后台=睡眠，重估=成长后重读旧事。」

> **弧线落点**：五轮之后，这条线收敛出**七条公理**——① **写傻读精**（在线只追加，判断移到离线）；② **库无界、装载有界**（被驳回后修正的版本）；③ **时间 = 因果的排序基底**（不是元数据；四轴字段 {时间、关键词、成因、结果} 平级）；④ **痛 = 定价机**（`严重度 × 不可逆性 × 代价`；纯逻辑必须先显式补上这份工）；⑤ **睡眠 = 离线巩固**（吸收与理解在时间上分开）；⑥ **全链留痕**（记录没有代价，就没法给记忆定价——所以每笔写入、失活与拒绝都留痕）；⑦ **格式自有**（资产在模型之外，换模型不换大脑）。一只苦力怕的爆炸，最终变成了七个设计公理与一个六库系统——这就是「外置大脑」被推出来的全过程。

## 2. 相关工作

本章定位本项目在四条相关线上的坐标——智能体记忆系统、离线巩固、上下文治理、认知与校准基础——并给出对照总表（§2.5）。

### 2.1 智能体记忆系统

MemGPT [1] 提出「LLM 即操作系统」的虚拟上下文分页；Generative Agents [2] 以「记忆流 + 检索评分 + 反思」首次给出记忆-反思闭环；MemoryBank [3] 引入艾宾浩斯式衰减；Zep [4] 以时序知识图谱组织记忆；Mem0 [5] 给出生产级提取-合并管线；A-MEM [6] 采用 Zettelkasten 式动态链接；MIRIX [7] 以六种认知类型记忆 + 多智能体管理器提出组合式记忆。**对照**：这些系统的评估焦点是「检索与个性化效果」；我们在同等机制之外，把**审计性**（来源态、修订链、双时态、门控）列为一等目标。此外，近期工作开始关注**循环与退化输出**的实时检测 [23,24]：我们不把检测做成干预闸门，而是以「只观测、不干预」的干跑观测环将之纳入同一个可审计框架（§3.9）。

### 2.2 离线巩固 / 睡眠

Sleep-time Compute [8] 提出在空闲期预计算「已学上下文」；OpenAI 的 Dreaming（2026-06，多源报道）把「后台做梦」蒸馏送入亿级产品；Letta 以双智能体（primary + sleep-time）实现「睡眠时改主记忆」，并提供 `/dream` 显式反思命令。**对照**：我们的睡眠器（§3.8）选择**追加式蒸馏**（统计与候选产出入队，不改写既有条目），与其改写式路线互为镜像。

### 2.3 上下文治理与迭代更新

ACE [9] 论证了「整体重写」导致 context collapse 与 brevity bias，主张结构化增量更新——其开源实现经我们源码级核实**只支持 ADD**（UPDATE / MERGE 均为 TODO），且每条 bullet 携带 helpful/harmful 使用计数。**对照**：ACE 提供了「纯追加上线可行」的独立证据；我们在此基础上补充了**更正机制**（修订链）与「被用没有」仪表的候选形态。

### 2.4 理论与认知基础

Tulving 的情景/语义记忆二分 [10]、互补学习系统（快慢双系统）、扩展心智 [11]（记忆可以合法地居于体外的工具），以及 CoALA [12] 对语言智能体认知架构的形式化，构成设计的概念基座。校准与幻觉文献 [13,14]（模型自评知识边界；二元评分下「猜」的期望收益为正）为来源态纪律提供了动机。

## 3. 设计

本章给出设计：先总原则（§3.1），再展开六库分工（§3.2）、演化与纪律机制（§3.3–§3.5、§3.7）、检索与离线巩固（§3.6、§3.8）。

### 3.1 总原则

- **库无界、装载有界**：存储无限，唯一硬约束是「每轮进上下文的量」；整读权只留给极小的无条件反射页。
- **写入与整理分离（写傻读精）**：在线只追加、不判断；判断（蒸馏、合并、复核）移到离线睡眠。
- **追加不改原文**：更正 = 新版本引用旧版本（supersedes）；原文永久可见，链条可回放。
- **模型无关**：全部资产（数据 + 工具面 + 钩子 + 纪律文本）在模型之外；模型只提供「读写与判断」两种能力。

### 3.2 六库分工

| 库 | 回答的问题 | 关键字段 | 复核节奏 |
|---|---|---|---|
| canon 稳定库 | 「什么是稳的」 | claim / source.type（复现/官方/他人/共识）/ source.ref / last_reviewed | 慢（年检级） |
| mirror 镜像库 | 「这类处境是怎么回事」 | situation → behavior → outcome → social_reaction → emotion | 随改口修订 |
| orphan 孤案 | 「什么是反常的」 | summary / observed / hypothesis / would_confirm / would_refute（零权重） | 回炉三通道 |
| pricing 定价表 | 「这个行为值多少」 | behavior / valence / severity_default | 随事件回写 |
| lexicon 情绪词表 | 「这叫什么情绪」 | term / trigger / behavior / resolution | 随用随补 |
| frontier 文献基石 | 「证据在哪」 | url / year / topic / status / next_review / supports | 到期复审 |

### 3.3 双时态与修订链

- **双时态**：`event_time`（事件时间，作者写、可选）× `logged_at`（记录时间，写入路径自动盖戳）。修订链的每一行都带 `logged_at` ⇒「某条何时被改」可查。
- **修订链**：任何记录可携带 `supersedes: <旧 id>`；「当前版本 = 未被他人 supersede 的记录」；修订从任意链上版本出发都自动落到链尾。悬空引用由校验器拦截。
- **写入门控**：数据目录的直写被宿主插件拦截（gate）；一切写入经校验函数（字段 / 枚举 / 格式）。

### 3.4 来源态四标签与排序钉子

输出侧强制四态：**学过**（权重内、未核验，只当假设）/ **接触过**（弱印象，权重更低）/ **记得·库内**（有出处与版本，可直接引用）/ **搜到**（网页，来源可靠性 × 信息可信度分级）。排序钉子：**无据的确定 ≪ 有据的不确定**；「确定不知道」也是合法输出（四层查尽 + 留痕）。该纪律以「渲染时读库」的方式注入系统提示：改纪律 = 追加一条修订，注入文本自动跟进。

### 3.5 情绪定价与孤案

- **定价**：`price = severity × irreversibility × cost`，输出 valence（±1）与 arousal；用于给事件与行为贴价签、驱动长期排序与规训回路。
- **孤案**：无同类可比的个案以「带钩子的问号」归档（观察到什么 / 假设什么 / 什么能证实 / 什么能证伪），默认零权重——错存代价 ≈ 0，错杀代价 ≈ 永久，故为保险而非矿藏。
- **回写（2026-10-07 起）**：定价结果可经修订链回写任意条目（CLI `price … --apply-store/--apply-id`，MCP 同形参）——条目携带 `valence / arousal` 后参与检索 boost（arousal×0.5 + 负价 0.25，`emotionBoost` 纯函数）；`kit` 输出负价 top3 作「**病史注入**」，负价条目在简报中带 ⚠。

### 3.6 检索与回忆

- **四源路由**：模型内记忆 → 技能 → 本地书库 → 网页；查了什么、结果如何，留痕。
- **计分**：整词命中 ×1 + 含中文 ≥3 字词的相邻二字回退 ×0.25（回退累计封顶 0.9）；**弱命中（<1，疑似相关）与强命中（≥1——恒含整词命中）**分层——「确定不知道」看强命中为零。
- **时间过滤与坐标**：`--since/--until`（事件时间优先、记录时间回退）；简报每条命中带时间坐标。
- **直读**：命中条目按 id 取全文（旧版本自动指向链尾）——对齐 Letta recall 的 needle→expand 模式。
- **镜像匹配**：`mirror match <情境>` 按**结构**召回最接近的镜像条目（五元组计分、situation 权重 ×2，支持 patterns 加权）——「照镜」不止于人读，也可被命令调用。
- **计分口径的不变式**：子词回退的累计贡献封顶 <1 ⇒「总分 ≥1 当且仅当至少一次整词命中」恒真——口径承诺由实现层保证并有回归断言（2026-10-07 复查捕获并修复的历史漏洞）。

### 3.7 强制力分层与投影律

「必定执行」做不到；强制力分层购买：① 软协议（提示层）提升概率；② 硬门控（执行层）对**可机检项**做到逐字级必定；③ 审计 + 定价（长期层）压长期分布。**投影律**：把不可检的德行投影为可检的工序（诚实 → 来源态字段；想清楚 → 计划段；别忘了教训 → 钩子必触发）。每条规则标注强制等级。

**已落地的审计形态（v0，2026-10-07）**：对模型输出做**可机检硬核**——抽取疑似库 id 与六库全量核对：引用不存在的 id → `output-audit` 线（编造引用嫌疑）；真实 id → `usage` 线（条目级使用计数）。宿主输出流为「只读观察」语义，故现阶段是**审计线**而非改写式闸门——边界与代价照实标注，不假装做到了没有的能力。

### 3.8 睡眠（离线巩固）

触发器：空闲（去抖 6h）+ 定时兜底（1h）+ **手动**（`sleep` 命令）。流程：钩子增量 → 计数与失败备注 → 审计复核 → 报告（同日不覆盖）→ 待办入队（孤案候选 / 复审提醒）→ 水位线推进。逻辑驻留核心库（可测、可直跑），宿主插件只负责调度与注入：两条 runtime 条子（睡眠摘要 / 库脉搏，后者在失败窗口内追一行**回查提示**）+ 唤醒条——「出错钩子」的注入级动作：失败回查是纪律，窗口内自动提醒、不拦截。

### 3.9 会话层：单会话记忆、弧线树与循环观测（2026-10-07 增补）

**问题**。上下文压缩（compaction）在长会话中折叠历史：官方摘要保走向、丢细节，而「细节与结论被折叠」与「吸收与理解」发生在同一时刻——这正是 §1.3 第 4 条公理（吸收与理解在时间上分开）在**会话内**尺度的对应物。

**设计**。会话层（实现代号「小阿卡夏」）在六库之外独立成层（第七数据面，`data/session.jsonl`；六库零改动）：

- **段抽取**：读取宿主会话档案（多帧 zstd 容器，**含被压缩折叠的内容**）→ 逐条 assistant/user 事件切段，段带 `kind`（intent / action / conclusion / process）、`gist`（截断摘要）、`keywords`、`tools` 与 **`ptr`（原档指针）**；同内容幂等、档案重写漂移时追加指纹新版。
- **结论优先检索**：`session lookup` 以结论/动作为第一入口；计分沿用记录级口径（Σ整词 ×1 + min(Σ回退, 0.9)）；`--process` 才纳入过程段——**过程段按需局部调取、绝不整体查阅**。
- **弧线树（抽象层 v0.2）**：在段之上机械递归——按回合切块 → L1「弧」→ L2「幕」（>2 块递归、≤3 层）；节点带 `gist`（展示）与 `extra`（评分扩面）、`treegen` 代际（重建＝新代，旧代留档不动）。导航纪律：**树＝入口 → 节点停靠 → 段 / ptr 下钻**；保真分级（顶结论 token 100% / 块级提及 62% / 段层 60%），**全保真唯一保证＝ptr 回原档**。
- **循环观测 P0（dry 干跑）**：三层环、零干预——流环（`agent/assistant-stream` 帧按 attemptId 累积，节流检查）、回合环（回合末全文兜底）、事后环（离线语义扫描，独立工具）。命中只写观测线（`loop-watch` / 帧类型探针），**绝不 steer / cancel / 注入**；干预版（P1）留待数据积累与逐条裁定。
- **观测环的第一批产出是修正观测环自己**：P0 上线首窗即暴露并修正五类跨组件缺陷——① 挂错事件面（插件收的是宿主**已退役**的 V0 流事件，现役面为进程内瞬态帧）；② 字段语义误读（流帧 revision **逐帧递增**，被误当「重开累积」信号，导致审计线恒空）；③ 字符类含空白导致 markdown 列表误报；④ 取数路径依赖宿主**不存在**的同步读者（已弃用接口）；⑤ 跨代同 id 的 **stale-read**。其中两处（①④）同时命中了同族既有插件的同型假设——「宿主接口真值必须逐项源码级核验」由此成为同族纪律。

### 4.1 体系结构

### 4.2 数据规范

JSONL 每行一条、append-only；校验器检查字段存在性、枚举与交叉引用；快照类条目 id 带日期；双时态字段规则见 §3.3。

### 4.3 工具面

CLI 16 命令（check / stats / lookup / brief / cross / summary / show / sleep / kit / promote / revise / price / orphan / frontier / audit / add；另有 `mirror match` / `metrics` / `session <index|lookup|context|tree|node|loopwatch|stats>` 三个子命令面）/ MCP 17 工具。全部可脚本化、可幂等重放。

### 4.4 与外部实现的关键对照（源码级）

- **ACE**：官方实现仅 ADD；我们的「修订链」在其外补上了更正维度。
- **Letta**：记忆文件系统 + recall 子代理（日期过滤、needle→expand）+ `/dream`；我们以「时间过滤 / show / 手动 sleep」对位，并保持 JSONL + 校验的机器可检形态。
- **OpenAI Dreaming**：产品级改写式巩固；（本文系统）与之在「离线巩固」上同向、在「不可变原文」上分道。

### 4.5 循环检测：与两个开源实现的源码级对照（2026-10-07 增补）

- **opencode PR #21112（未合并）**：在流层做周期扫描（缓冲 2×max_period、两位点 O(1) 预检、逐位相似度、`takeUntil` 硬断流）——算法严谨、测试完备；其执行面依赖流控制权，且在宿主之外不可移植。对照：我们复用其**判据思想**（周期性/相似度/廉价预检），但把执行面保留为**观测**。
- **dsh-thinking-loop-guard（MIT）**：提供规则族（长程块重复 / 行重复 / 空转超时 / 工具调用环）与中断姿势的实证（`steer` 不能中断流；`cancel(keepInbox)` 可行）。但源码级核验发现：其「实时内容检测」接的是宿主**已退役**的 V0 流事件——在现役宿主上为死路。
- **结论（借法不借装）**：吸收规则族与中断知识；检测核心自持（`loop-detect.mjs`，纯函数、可离线复用）；宿主适配层以**活体验证**为准（探针 + 首线核对），不以文档声称或历史行为为准。

## 5. 评估（初步）

本章为初步评估：自检与测试（§5.1）、运营数据（§5.2）、治理循环案例（§5.3），以及明确列出的局限（§5.4）——本文是系统与方法论论文，不冒充基准论文。

### 5.1 自检与测试

`test.mjs` **77/77**（核心 / CLI / MCP / sleep / 会话层五段；含跨运行环境稳健的截断帧信号）；**四个**插件 selftest 全绿（会话层 18/18；含输出审计五节用例与门控箭头误拦回归哨兵）；六库 `check` 全过；留痕脚本幂等复跑全跳过。校准插曲一例：一条按某一 Node 版本 zstd 行为写死的断言，在另一版本下暴露失败——修复为使信号**跨版本稳健**（帧数不匹配 ∨ 文本完整性），并写入「跨环境断言」纪律。

### 5.2 运营数据（首 48 小时，单实例）

### 5.3 治理循环案例

测试期「冻结 → 受控解冻 → 两轮复查 + 举一反三再两轮」：两轮跨会话的真实治理循环中，第二遍换角度复查先后捕获——① **跨会话测试污染**（测试桩缺失 → 触发空报告写入真实日志）与一批文档漂移；② **口径承诺被静默突破**（子词回退可累计 ≥1，破坏「≥1 ⟺ 整词」承诺）与工具面数字残留——全部修复、物证归档、不变式入测试。纪律本身（复查 / 用法同步）在首轮被**立条入库**——此前它只有事件记录、没有规则条目，因而检索不到、不会被自动执行；次轮即以此纪律抓到新一类问题（「口径承诺必须被实现强制」）。这是「纪律必须入库」原则的连续实证。

第二例（同日，**同族举一反三**）：把会话层复查确立的五类错误（采样盲区 / 宿主假设 / 信号真值 / 字段补全 / stale-read）照向核心库与四个插件，又捕获并修复 5 处——其中两处属「**功能存在但恒零**」级别：输出审计的累积逻辑误读流帧 revision 语义，使审计线自上线起零产出；多 token 弱回退叠加突破「强命中 ⟺ 整词命中」的口径承诺。教训成条：**「恒零」也是故障信号**（需哨兵）；**观测线的首批数据必须先能复核观测环自身**；**夹具必须按宿主真值塑形**（一日内三例「夹具失真」由此立为独立失范项）。

### 5.4 局限

单实例、N=1；评估为自检与运营描述而非基准对照；睡眠目前仅统计级蒸馏（LLM 蒸馏未实现）；来源态的实际收益（幻觉率变化）尚无对照测量。会话层边界：旧格式（早期 chunk 型）档案仅部分可抽取；纯英文 / 低 CJK 文本落在窗口合格线（CJK ≥20%）的盲区内；帧类型探针每会话上限 8 类（防爆设计）。循环观测 P0 为**观测**而非干预——对空转的遏制效果尚无对照测量（P1 待数据与逐条裁定）。

## 6. 讨论

本章讨论三件事：两条巩固路线的分工（§6.1）、从真实事故提炼的失败模式与防线（§6.2）、以及路线图（§6.3）。

### 6.1 两条巩固路线的分工

产品路线（Dreaming）押「改写（re-profile）」；本文路线押「追加 + 修订链 + 双时态」。前者为个性化优化，后者为审计与可追责优化。二者并非互斥：改写层可以作为追加层之上的**视图**存在。

### 6.2 失败模式与防线（来自真实事故）

1. **静默失败**（宿主插件失活无日志）→ 全插件补观测线（armed / error 线）。
2. **覆写风险**（生成器重跑抹库 / 报告同日覆盖）→ 生成器改幂等合并、报告加时间戳后缀。
3. **表述漂移**（文档 / 注入文本落后于实现）→「用法同步」纪律 + 引用残留扫描零容忍。
4. **测试污染真库**（桩缺失触发真实写入）→ 修复 + 物证归档 + 兜底清理。
5. **事件真值漂移**（挂上已退役的 V0 流事件面；把逐帧递增的 revision 误读为「重置累积」信号）→ 纪律：宿主接口逐项**源码级核验** + 活体首窗验证（探针 / 首线核对），不以文档声称或历史行为为准。
6. **夹具失真**（测试按作者想象而非宿主真值塑形——一日内三例）→ 纪律：夹具＝宿主真值快照（逐帧递增、字段缺失、事件真名）；修复缺陷必附**回归哨兵**。

### 6.3 路线图

LLM 蒸馏（睡眠的「内容化」）；输出审计从「id 存在性」扩展到**语义级断言核验**；记忆市场时代的位置（若记忆成为可携带资产，则「格式 + 纪律」是比「模型」更稳定的层）。条目级使用计数 v0 已落地（`usage` 线），下一步是 helpful/harmful 双计数形态。会话层路线：插件侧**自动建树**（v0.3）；循环观测 **P1 温和恢复**（nudge → `cancel(keepInbox)` 硬断 → 推理降档 → 放行——须待 P0 数据积累与逐条裁定；不采用硬失败式 abort）。

## 7. 结论

阿卡夏之书把「记忆」当作一个需要**治理**的工程对象：它以六库分工解决「记什么」、以修订链与双时态解决「改了怎么办」、以来源态与定价解决「信多少」、以三层强制力解决「怎么保证执行」，并以睡眠完成离线巩固。全部资产在模型之外——换模型不换大脑。我们开源这条路径，供任何需要「可审计记忆」的语言模型智能体直接使用与批评。
