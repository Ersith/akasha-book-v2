# 「记忆有没有用」——一次被打脸的实验，和它给出的答案

> 2026-10-11 · 阿卡夏之书（外置大脑）· 结论一句话：**库内容确实能被用上并提升表现（+2 / +4，两轮方向一致）；但我们还不能说它让人"更对"——因为评分标准本身就是从库里提炼的。**

---

## 一、起点：一个没被验证过的信念

阿卡夏之书（六库 + MCP + 门控 + 睡眠器）建了五天，被引用 145 次，修了不少坑。但"**用了它到底有没有更好**"这个问题，手上只有 **n=2 的弱证据**——那两条（B01/B04）证明的还只是"**库里的东西可达**"，不是"**用了之后做得更好**"。

于是决定做实验。铁律先立好（防止自欺）：
- 题面**不含答案**（评分表另放）；
- 无记忆臂若失败或明显返工，该题才保留；
- **负结果同样入 canon**，不做美化。

## 二、三轮演进：每轮都被上一轮的缺陷打脸

### v1：两组平分（16:16）——但结论作废
10 个历史失败案件，两臂（有库 / 无库）各答，判卷者盲评。结果有效 8 案全是 A 档、16:16 平。
判卷者（独立 subagent）随即抓出**三处硬伤**：
1. **配题缺陷（我的脚本 bug）**：rubric 按工具名兜底配对，两案的评分标准配到了**别的案子**；
2. **天花板效应**：题面把路径/上下文都给全了，**通用经验就能答满**，本包无区分力；
3. **隔离不完整**：无库臂只被封了"阿卡夏"一路。

### v2：题面硬化 + 三套记忆全封——结果 +2，但设计又被打脸
题面改成"**只给工具名 + 一行报错**"（路径全剥）、9 案（去重后）、三套记忆工具明令禁用。
揭盲：**有库 14 : 无库 12（+2）**。
但无库臂的如实申报揭穿了设计：**三套记忆工具在本 harness 里对它全部可见**（"无记忆"只是它选择不调用），而且**上下文自带注入**（"库脉搏"点名最近写入条目 id、"回查提示"点名陷阱条目 id）——
**⇒ 所谓无库臂，测的只是"会不会主动去查"（pull），封不住"被塞进上下文"（push）。**

### v3：把实验搬出这个 harness——结果 +4
两臂都改用 **Codex**（独立进程：**无 DSH 注入、无 MCP 记忆工具**）：
- 臂 A = 题面 **+ 把库内对应条目正文原样贴进 prompt**；
- 臂 B = 只有题面。
**模型恒定、环境恒定，唯一变量＝有没有那几段库内容**——这才是干净对照。
揭盲：**有资料 18 : 无资料 14（+4）**；7 个计分案 **14 : 10**。

## 三、结果怎么读（三层，别混）

| 层次 | 结论 | 证据强度 |
|---|---|---|
| **能不能用上** | ✅ 能。有库臂的答案**逐条对上了库内条目的动作项**（判卷者核验了它引用的每条条目都真实存在、所述属实） | 强（引用可核） |
| **用了会不会更好** | ✅ 在这个评分标准下更好（+2 / +4，两轮方向一致，v3 超过事先注册的阈值） | 中—强 |
| **是否"更对"** | ❓ **不知道**。**评分标准就是从库里提炼的** ⇒ "更贴 rubric"有一截是**循环论证** | **弱（本轮最大局限）** |

**一句话**：我们证明了**库内容能保真地变成答案里的动作**；**没**证明**它在独立标准下让人更正确**。

## 四、比分数更值钱的方法学产出

1. **列分 ≠ 臂分**：每案的"解答1/解答2"对应哪一臂是**逐案随机**的 ⇒ 判卷者给的列总分（13:13，看着像平手）折回臂分是 **14:12**。这个坑不写脚本就会读错（已做 `judge-unblind.mjs`）。
2. **作者不自证**：三轮里，独立判卷者抓出了**配题 bug、缺失的评分表、盲化缺陷**，还逐条核验了引用真伪。**同一个"我"当裁判，一定漏。**
3. **产物 ≠ 通知**：有个臂**实际完成了作答并落盘**，只是完成通知丢了，被我误判"死掉"并重派——**判死前先看产物**。
4. **并发写同一路径是隐患**：两次派发覆盖同一文件（所幸接手者按纪律先备份）。
5. **本 harness 内无法构造"无记忆"对照组**：工具面全可见 + 上下文注入不可关闭 ⇒ 想测"没有记忆"，**必须换执行器**（v3 的 Codex 就是解法）。
6. **三层记忆的边界（实测）**：Hindsight（仓）**没有**条目级教训（只有项目级页面）；OpenViking（人）**有**"事件叙述 + 条目 id 提示"；**教训正文只在阿卡夏**（我）这一层。

## 五、下一步（已停着，待定）

**v4 的唯一升级点 = 换独立 rubric**：评分标准改成**与库无关**的外部标准／第三方独立评分，把"**更贴库**"变成"**更对**"。
同时修两处盲化缺陷（剥掉答案里的臂签名行与"→ 参考条目"引用行）、补齐评分表、统一计分分母。

## 六、附：这轮实验对"记忆系统"本身的意义

- 本轮最硬的一条不是分数，而是**规矩**：**先注册判据、后读数据**；**负结果入档**；**判卷者独立**；**列分不等于臂分**；**产物先于通知**。这些让"记忆有用吗"从一句信仰，变成了**能被自己的设计缺陷打脸、也能被别人的复核纠正**的实验。
- 也顺带确认了系统分工的现实边界：**教训在阿卡夏、偏好与身份在 OpenViking、架构与决策在 Hindsight**——三者不是冗余，而是**不同层的记忆**；把它们混为一谈（v1/v2 就差点如此）会得出错误的"记忆无用"结论。

## 七、补章：问题问错了（2026-10-11 用户裁定后的修正）

**原问题「记忆有没有用（=让人更对）」是错的。** 用户的论断：
- **记忆本身不可能让人更对**——换到人也一样：**能力提升后回看过去做的事，会发现不少技术上不合理**；
- **记忆的目的就是保真与准确记住**；**"怎么处理问题"是记忆 + 知识 + 当下判断的合成**，不能把合成结果记在记忆头上；
- **记忆还负责自我同一性**——人靠记忆保证"随时间成长、认知变化，自己也依旧是自己"（对应我们的自我层 `akasha:self`）。

**⇒ 记忆的三个正确 KPI**：
| KPI | 含义 | 现成对应 |
|---|---|---|
| **K1 保真** | 库内容被引用/复述是否准确；库内没有时是否敢说没有 | 本轮新增**保真度实测**（见下） |
| **K2 可达** | 需要时想不想得起来 | C1/C3 与漏召率指标（观察期在跑） |
| **K3 可复查/可修订** | 过去的判断能被回看并纠正 | 修订链 + 矛盾检测（H5 候选） |

**保真度实测（用户指定的检验：回答里有多少是库内原文）**
方法写死：答案句与库内条目原文的最长公共子串 **≥10 字** 即记"源自库内原文"。

| 轮次 | 有库/有资料臂 | 无库臂 | 倍数 |
|---|---|---|---|
| v3（Codex 两臂） | 句级 12% · **字符级 39%** | 句级 3% · 字符级 14% | **2.8×** |
| v2（subagent 两臂） | 句级 7% · **字符级 24%** | 句级 1% · 字符级 6% | **4×** |

**⇒ K1 保真成立**：库内容**确实被搬进了答案**（跨两轮、跨两种执行器一致）——**这才是记忆的专属证据**。
**且与 v4 互证**：无库臂那 6–14% 的重合，正是"**通用工程常识与库内原文的重叠区**"——**库里相当多条目写的就是通用最佳实践**，所以独立 rubric 下两臂才能同分。**两个独立观察互相印证。**

**因此 v1–v4 的最终定位**：它们不是"记忆有没有用"的判决，而是**一次把问题问错的实验**——但它逼出了三件有价值的事：**记忆的 KPI 定义**、**评价标准的同源性检查**、以及**"合成输出不能归因给单一能力"这条方法论**。

## 八、下一步（未做 / 已按用户裁定暂缓）

**用户 2026-10-11 的正解（比本节上文的"三个 KPI"更准）**：
- **记忆的正确性＝对自己认知状态的自知**——「是否记得这事、有没有接触过、有没有学过、有没有搜过」（＝库内**来源态四标签**的存在理由），**不是结论正确**；
- **记忆是"回头看"的底座**：能力/插件/知识库增长后，**回头看旧记录能长出新的解法**（当日实证：CyberStrikeAI 的门控设计 → gate v1.3.0-h1；其"已拦截不计入失败分母" → 口径原则；保真度检验 → 改写记忆 KPI 本身）。

**因此**：
- **K1**（逐字保真 + 编造测试）——**暂缓**（放一放，不删）；
- **K3**（回看-纠正动作样本统计）——**暂缓**；
- **K2**（可达）——**继续**：由 C1/C3 预检与坑提示、漏召率指标、每周自动周报承担。
