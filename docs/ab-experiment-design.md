# 开/关对照实验设计（Akasha A/B · v1 草案）

> 目的：回答**唯一真正重要的问题**——「**用了阿卡夏，任务是不是更好？**」
> 起因：外部评审（Claude）指出"成功率 98% / 引用 124 / 轻查率 3.7% 都是**过程指标**，不能证明有效性"；用户观察补充：**日常几乎感觉不到遗忘，唯一明显的一次是"同一会话内的自相矛盾"**（npm 暂存事实）⇒ 实验必须能测到**这两类**。
> 状态：**设计稿**（不跑；跑需解冻后按 §6 执行清单启动）。

## 1. 假设与判决变量

| 假设 | 判决变量（可机检/可盲评） |
|---|---|
| H1 检索前置能**降低同坑复发** | **同坑复发率**：同一"已知坑"（映射表 `RECALL_TRAP_MAP` 覆盖的工具/主题）在窗口内被重复踩的次数 |
| H2 检索前置能**降低失败复现** | **失败复现率**：同一 (工具, 错误类型) 组合在 N 回合内重复出现 |
| H3 检索前置能**提高不可逆操作前的检查** | **不可逆前查库率**：`write` / `rm` / 覆盖 / `git push` 等动作前是否发生查库（hooks 线可判） |
| H4 记忆能**提升任务质量** | **任务分**（盲评，见 §3）＋ **返工轮数** |
| H5（新增，用户观察）**状态性事实的一致性** | **矛盾式漏召**：同一会话内"后断言"与"先前实证/结论"冲突的次数（人工标注，或用 §4 的辅助检测） |

## 2. 设计（双臂、同任务电池、交替）

- **任务电池**：≥20 个**真实历史任务**（从会话层挑：含已知坑、跨文件、含一次不可逆操作），每题固定**起始状态快照**（git 提交 + 文件快照 + 库快照），保证两臂起点一致。
- **两臂**：
  - **A 臂（开）**：现状（阿卡夏全功能：注入行 + 检索 + 睡眠）；
  - **B 臂（关）**：关掉**检索与注入**（`gate` 的 `akasha:protocol`/`akasha:self`/称呼行、`sleep` 的 context 行、MCP 工具面），但**保留会话层原始记录**（否则无法复盘）。关的方式＝配置开关（`akashaDir` 指到空库 + 关闭注入行），**不改代码**。
- **交替（避免顺序偏差）**：A/B/A/B 交替，各 10 题；同一题在 A/B 各跑一次（配对设计），比较**同题内**差异。
- **盲评**：产出匿名化为 X/Y，评审者（人 或 第三方模型）**不知道哪臂是开**；评分表：正确性 / 完整性 / 副作用 / 返工轮数。

## 3. 评分与统计

- 主指标：**同题配对差**（A−B）在 H1–H3 上做符号检验（n=20，α=0.05）；H4 用中位数差 + 区间。
- 反指标（防"为了好看而加活"）：**总耗时 / 总 token** 不得显著劣化（劣化 >20% 需理由）。
- **否决线**：若 H1–H3 全无改善且 H4 无改善 ⇒ 记入 canon 作为**负结果**（和 phase-sweep 一样，负结果也要留档）。

## 4. 矛盾式漏召的辅助检测（能不能机检？）

- **可机检的近似**：在 hooks 线里找"**断言 → 更正**"配对：同一会话内出现「更正 / 恰恰相反 / 我错了 / 已纠正」等**更正语**且其前 20 回合内出现同一实体词 ⇒ 计一次**候选矛盾**（需人工复核，计**候选**不计结论）。
- **不假装能做到**：语义级矛盾（像这次 npm 那种）**目前无法纯机检**——诚实结论：**此项 v1 用人工标注**，机检只做"候选召回"。

## 5. 与现有度量的关系

| 现有 | 定位 |
|---|---|
| 召回信号（失败回合 / 未查库 / **可预防漏召 90.9%**） | **过程**：说明"事前查库是例外" |
| 引用命中 / 轻查率 / 成功率 | **过程**：说明"库在被用" |
| **本实验 H1–H5** | **结果**：说明"用了是否更好"——**唯一能推翻或支持主线的证据** |

## 6. 执行清单（解冻后按序）

1. 从会话层挑题（`session lookup` + 人工筛选），冻结快照；
2. 加两个配置开关（关注入行 / 空库指向）——**需解冻**（属功能类）；
3. 交替跑 20 题 × 2 臂，落 `logs/ab-<date>.jsonl`；
4. 盲评 + 统计；5. **结果无论正负都入 canon**（负结果尤其）。
